# Проверка проекта после улучшений

Дата: 27 октября 2026. Этот отчёт описывает последнюю проверенную реализацию; прежние сообщения об отсутствии Django, Docker и Chromium больше не относятся к текущему окружению.

## Автоматические проверки

| Проверка | Результат |
| --- | --- |
| Django на отдельной файловой SQLite | **95/95**, 20.419 с; без пропусков |
| Автономные тесты runner, резервирования и восстановления | **25/25**, 0.204 с |
| Настоящий Docker | **14/14**, 20.348 с |
| Браузерные сценарии с Chromium и подменённым API | **14/14**, 56.911 с |
| Django system checks | Успешно |
| `makemigrations --check --dry-run` | Изменений нет |
| Compose `config --no-interpolate --quiet` | Успешно |
| Синтаксис Python и JavaScript | Успешно |

Django-набор проверяет права, версии работ, дедлайны, атомарное завершение, повторы отправок, конфликты вкладок, публикацию, кабинет преподавателя и конкурентные HTTP-запросы. Новые проверки охватывают:

- Ограничение ввода и эталонного вывода байтами UTF-8, включая повторную валидацию при публикации.
- Историю выставления, снятия и сброса оценки с текстом и версией ответа; отказ устаревшей оценки без записи в журнал; перенос текущей оценки в исходное состояние журнала.
- Отсутствие исходников и результатов в SQL-запросах списка отправок, постраничную историю, проверку владельца и отложенное раскрытие.
- Атомарный CSV-импорт, пароли, отсутствие перезаписи пользователей и назначения административных прав; CSV-экспорт с фильтрами и защитой от формул.
- Общий лимит входа для студенческой страницы и админки, отдельные логины за одним IP, истечение окна, успешный вход, CSRF, доверие заголовку только в явной конфигурации и 12 конкурентных запросов при лимите 8.
- Сохранение эталона и inline-тестов до постановки проверки в очередь, неизменяемый payload, повторную проверку при изменении данных, приоритет отправок студентов, Docker вне транзакции и восстановление прерванной проверки эталона.
- Контроль свежести worker, задержки очереди и отсутствующей подтверждённой резервной копии.

Docker-набор исполняет настоящий C++ только внутри контейнеров. Проверяет корректные/неверные решения, компиляцию, runtime, время, память, stdout, дочерние процессы, отсутствие сети и записи в корень, read-only бинарный файл, свежий tmp между тестами и очистку ресурсов. Новый сценарий подтверждает успешный вывод ровно 65 536 байт UTF-8 и отклонение слишком большого эталона валидатором.

Браузерный набор проверяет Monaco, независимые задачи, автосохранение, локальное восстановление, конфликт вкладок, повтор неизвестной отправки после перезагрузки, таймаут сохранения, завершение, продление, мобильный fallback, свой ввод, переход по диагностике, историю оценок, форму преподавателя, предупреждение очереди, потерю связи, статусы задач и ссылку на полную историю. API подменено; реальную запись и Docker подтверждают проверки ниже.

Ожидаемые ошибки инфраструктуры в отрицательных тестах записываются в журнал. Итог тестовых наборов — успешный.

## Репетиции с настоящими HTTP, Django и Docker

| Сценарий | Результат |
| --- | --- |
| 30 студентов, остановка занятого worker и повтор прерванной отправки | Успешно, **69.253 с** |
| p95 HTTP-запросов этого сценария | **1.374 с** |
| Максимум ожидания очереди | **57.933 с** |
| Максимум выполнения одной проверки | **2.519 с** |
| Настоящая сдача через Chromium, Django, worker и Docker | Успешно, **15.817 с** |

В обеих репетициях worker сначала успешно проверяет эталон; публикация использует результат этой проверки. Подтверждены повтор запроса без новой отправки, сохранение теории, завершение, выставление оценки через HTTP, окончательный зачёт и восстановление согласованной резервной копии. При браузерной сдаче дополнительно выполнены примеры и отправка кода из Monaco.

Отчёты: [30 студентов](../test-results/exam-load-improvements.json), [настоящая браузерная сдача](../test-results/exam-browser-improvements.json). Снимки интерфейса: `test-results/workspace-desktop.png` и `test-results/workspace-mobile.png`.

Отдельно прошёл сценарий `--problem-json` с другим эталоном, двумя тестами, лимитом 0.5 с и памятью 64 МиБ: два студента, 5.285 с, успешные итог и восстановление. [Отчёт](../test-results/exam-custom-improvements.json). Регрессионная проверка CSV с совпадающими после нормализации Unicode логинами также прошла после последнего изменения импортера.

Это демонстрационная задача сложения с тремя тестами, лимитом 2 с и памятью 128 МиБ. Репетиции используют отдельную временную базу и отдельный Docker-префикс. Рабочие учебные данные не используются. В рабочей базе сейчас одна демонстрационная задача; производительность на реальных заданиях кафедры не измерена. Для этого добавлен `--problem-json`; формат и команды приведены в [operations.md](operations.md).

## Обновление и оставшаяся проверка на сервере

Перед изменениями создана согласованная копия `backups/before-project-improvements-20261027T153558Z.sqlite3` с правами 0600. Миграция `lab.0004` применена к локальной базе. Исходные учебные задания и опубликованные версии не переписывались.

После миграции прежние поля всех строк пользователей, членства групп и учебных таблиц сравнены с резервной копией: совпадают. `PRAGMA integrity_check` вернул `ok`.

HTTPS и реальная SSH-выгрузка резервной копии зависят от рабочего домена и доступов; в этой проверке они не настраивались. Systemd-таймер и внешнее уведомление о сбое также требуют настройки на сервере. Перед зачётом проверьте там `check --deploy`, настоящий Docker-набор, свежесть внешней копии и репетицию реального задания. Инструкции: [README](../README.md), [operations.md](operations.md).
